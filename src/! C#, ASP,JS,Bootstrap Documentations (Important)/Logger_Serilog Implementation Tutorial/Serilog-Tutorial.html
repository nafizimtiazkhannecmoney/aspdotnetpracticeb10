Serilog + ASP.NET Core

Complete step-by-step guide to add professional file logging to any ASP.NET Core 6 / 7 / 8 project

Why this tutorial exists
The default Microsoft logger only writes to the console. Serilog gives you structured logging, rolling files, clean templates, and easy configuration via appsettings.json. This page is your permanent reference – copy-paste ready.

1. Install the required NuGet packages

Open the terminal in your project folder and run:

dotnet add package Serilog.AspNetCore
dotnet add package Serilog.Sinks.File
Serilog.AspNetCore is the most important package – it integrates Serilog with the ASP.NET Core host and DI system.

2. Configure Serilog in appsettings.json

Replace or add the following section in your appsettings.json (you can keep the old "Logging" section – it will be ignored once Serilog takes over):

{
  "Serilog": {
    "Using": [ "Serilog.Sinks.File" ],
    "MinimumLevel": {
      "Default": "Information",
      "Override": {
        "Microsoft": "Warning",
        "System": "Warning",
        "Microsoft.AspNetCore": "Warning"
      }
    },
    "WriteTo": [
      {
        "Name": "File",
        "Args": {
          "path": "C:/Logs/MyApp-.log",
          "rollingInterval": "Day",
          "retainedFileCountLimit": 7,
          "outputTemplate": "{Timestamp:yyyy-MM-dd HH:mm:ss} [{Level:u3}] {Message:lj}{NewLine}{Exception}"
        }
      }
    ]
  }
}

Key options explained

Setting Meaning
path Log file location. The - before .log is replaced by the date (e.g. MyApp-20260915.log)
rollingInterval Day = new file every day. Other options: Hour, Minute, Month
retainedFileCountLimit How many old log files to keep (7 = one week)
outputTemplate How each log line looks. {Level:u3} = INF, WRN, ERR…
Windows tip: Make sure the folder C:\Logs exists and your application has write permission to it. On Linux/macOS change the path to something like /var/log/myapp/MyApp-.log.

3. Wire Serilog in Program.cs

This is the most common place people go wrong. You must both create the bootstrap logger and tell the host to use Serilog.

using Serilog;

Log.Logger = new LoggerConfiguration()
    .ReadFrom.Configuration(new ConfigurationBuilder()
        .AddJsonFile("appsettings.json")
        .Build())
    .Enrich.FromLogContext()
    .CreateLogger();

try
{
    Log.Information("Application Starting...");

    var builder = WebApplication.CreateBuilder(args);

    // ⭐ This line is critical – without it, controllers still use the default logger
    builder.Host.UseSerilog();

    // Register your services
    builder.Services.AddControllers();
    // builder.Services.Add... etc.

    var app = builder.Build();

    // Optional but highly recommended – logs every HTTP request
    app.UseSerilogRequestLogging();

    // Middleware pipeline
    // app.UseAuthentication();
    // app.UseAuthorization();
    app.MapControllers();

    app.Run();
}
catch (Exception ex)
{
    Log.Fatal(ex, "Application terminated unexpectedly");
}
finally
{
    Log.CloseAndFlush();   // ensures all logs are written before exit
}
Why two steps?
• The early Log.Logger = … captures startup messages (before the host is built).
• builder.Host.UseSerilog() makes ILogger<T> in controllers and services use Serilog instead of the default Microsoft logger.

4. How to use the logger in your code

In Controllers / Services (recommended)

public class TestController : ControllerBase
{
    private readonly ILogger<TestController> _logger;

    public TestController(ILogger<TestController> logger)
    {
        _logger = logger;
    }

    [Authorize]
    [HttpGet("private")]
    public IActionResult Private()
    {
        _logger.LogInformation("Accessing private endpoint by user: {User}", User.Identity?.Name);

        var userId = User.FindFirst(ClaimTypes.NameIdentifier)?.Value;
        // ... rest of your code

        return Ok(new { /* ... */ });
    }
}

Using the static Log class (anywhere)

Log.Information("Something happened with value {Value}", someValue);
Log.Warning("This is a warning");
Log.Error(ex, "An error occurred while processing {Id}", id);

5. Common problems & solutions

Problem: “Application Starting…” appears, but controller logs do not.
Solution: You forgot builder.Host.UseSerilog();
Problem: No log file is created at all.
Solution:
  • Check that the folder exists and is writable
  • Temporarily add a Console sink to see if logs appear in the terminal
  • Lower MinimumLevel.Default to "Debug" for testing
Problem: Too many Microsoft framework logs.
Solution: The Override section already silences them. You can make it even quieter: 
"Override": {
  "Microsoft": "Error",
  "System": "Error",
  "Microsoft.AspNetCore": "Error"
}

6. Bonus – Add Console + File sinks together

Useful during development so you see logs both in the terminal and in the file:

"WriteTo": [
  {
    "Name": "Console"
  },
  {
    "Name": "File",
    "Args": {
      "path": "C:/Logs/MyApp-.log",
      "rollingInterval": "Day",
      "retainedFileCountLimit": 7,
      "outputTemplate": "{Timestamp:yyyy-MM-dd HH:mm:ss} [{Level:u3}] {Message:lj}{NewLine}{Exception}"
    }
  }
]

You also need the package:

dotnet add package Serilog.Sinks.Console

7. Quick checklist (copy this)

  1. ☐ Install Serilog.AspNetCore + Serilog.Sinks.File
  2. ☐ Add the "Serilog" section to appsettings.json
  3. ☐ Create the bootstrap logger at the top of Program.cs
  4. ☐ Call builder.Host.UseSerilog()
  5. ☐ (Optional) Call app.UseSerilogRequestLogging()
  6. ☐ Wrap everything in try/catch/finally with Log.CloseAndFlush()
  7. ☐ Inject ILogger<T> in controllers and services
That’s it! Once you follow these steps, every _logger.LogInformation(...) and every Log.Information(...) will appear in your rolling log file.
